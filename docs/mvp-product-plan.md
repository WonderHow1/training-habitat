# 像素宠物健身 App｜MVP 产品方案

版本 v1.0 · 2026-11-16

这是项目早期的产品方案，记录首测目标、功能假设和验收构想。当前个人版的功能、安装与验证见 [iOS 说明](../ios/README.md)。

## 1. 产品目标

面向中国大陆使用 iPhone 的大学生，首批招募**近两周排过训练、也漏过练的人**。已有计划的学生常用备忘录或 Keep，前者记录后反馈有限，后者的功能超出部分学生安排和记录训练的需要。课业打乱计划、训练记录漏填，都可能让一周的安排搁置。

产品是一款简体中文 iOS App。用户把训练排进日程，手动记录或同步已完成的训练，让像素宠物成长。确认漏练会扣血，血量耗尽时宠物死亡。**首测要验证的是，这套玩法能否提高两周计划训练完成率，以及用户在漏练或宠物死亡后是否愿意继续练。**

## 2. 首版范围

| 功能 | 首版交付 |
| --- | --- |
| 首次使用 | 领养一只宠物，设置第一个训练计划。可跳过 Apple 健康授权，之后仍可使用手动记录。 |
| 一周计划与首页 | 逐次设置日期、项目和目标时长。首页展示宠物、今日训练及下一次训练。无安排时显示「今天无计划训练」。 |
| 改期与提醒 | 截止前可在当周改期。训练日提醒一次，进入待补记后提示补记截止时间。提醒关闭时，首页仍显示计划状态和期限。 |
| 训练记录与匹配 | 手填实际日期、时间、内容和时长，或从 Apple 健康导入可读取的训练记录。用户确认对应哪项计划，重复来源只计一次。 |
| 结算与更正 | 处理完成、待补记、漏练及迟到设备记录更正。详情页显示截止时间、关联记录和扣血原因。 |
| 像素宠物 | 一套像素宠物形象和少量成长阶段。支持成长、扣血、死亡、重新领养及误判更正后的恢复。 |
| 训练历史 | 查看已记录的训练、所属计划和结算结果。宠物死亡、重新领养或恢复后均可查看。 |

后续版本再考虑课程库、自动生成训练计划、专业训练分析、社交排行、多宠物收集和独立 Apple Watch App。

## 3. 用户流程

| 步骤 | 用户操作 | 系统反馈与下一步 |
| --- | --- | --- |
| 1. 领养与排计划 | 领养宠物，安排本周哪天练什么、单次练多久。 | 宠物初始 3 格血。首页展示今天和下一次训练，可快速进入记录与改期。 |
| 2. 开练或改期 | 到训练日按原计划练，或遇到课业冲突时提前改期。 | 改期更新同一项计划的日期和提醒。原日期的提醒取消，按新日期重新计算截止时间。 |
| 3. 记录并完成 | 手填训练，或从 Apple 健康导入后确认对应的计划。 | 核对实际时间与单次时长。达标即标为「已完成」，宠物获得一次成长。可在历史里看到同一场训练和对应计划。 |
| 4. 截止后补记 | 到期还没有达标记录，用户在 24 小时内补填或同步。 | 计划显示「待补记」及截止时间。符合条件的原定日期训练可完成计划。补记期间暂不扣血。 |
| 5. 结算漏练 | 补记期满仍没有符合条件且已确认的训练。 | 计划显示「已漏练」、对应日期和扣血结果。宠物扣 1 格血，归零时死亡。首页继续显示下一次训练。 |
| 6. 迟到设备记录更正 | 设备记录随后到达，用户在更正窗口内确认它对应的计划。 | 若符合条件，改为「已完成」，撤销该次扣血，补发一次成长。若该次更正使已死亡宠物恢复到至少 1 格血，出现恢复入口。 |
| 7. 死亡后继续 | 用户接着按原计划训练，也可以领养新宠物。 | 保留计划与历史。新宠物从 3 格血开始。若原宠物因更正可恢复而已有新宠物，用户选择继续养新宠物或恢复原宠物。 |

## 4. 业务规则

### 4.1 计划与改期

- 首测统一使用北京时间（Asia/Shanghai），周一至周日为一周。训练日的截止为次日 00:00，恰好到达截止时刻的训练结束时间按次日计。
- 用户仅可改动尚未完成、且原截止时间未到的计划。新日期须在原计划同一自然周内，且为今天或未来日期。改期保留原计划编号和目标时长。
- 改期后以新日期判断达标。当天新建或改到当天的计划，只有计划生效后开始的训练可计入。同一项计划改期多次仍只算一项。

### 4.2 完成、补记与更正

- 一场训练须在当前计划指定日期内开始并结束，且单次实际时长至少达到目标时长。由用户确认对应关系，运动分类可不同。一次训练最多完成一项计划，一项计划最多按一场训练发放成长。跨日或未达标的训练可保留在历史中。
- 手动记录和设备记录均可在计划截止前或补记窗口内确认。以实际训练时间判定，在计划截止后开始的训练可进入历史。
- 从计划截止时刻起满 24 小时，仍无已确认的达标记录，结算为「已漏练」。从补记窗口关闭起至计划截止满 7 天前，仅来自设备或运动 App 自动记录的训练可更正。用户需要在窗口内确认关联，Apple 健康里的手动录入遵循普通手动补记的时限。
- 更正将原计划改为「已完成」，撤销同一次漏练造成的扣血并补发一次成长。超过 7 天的记录仍可导入历史，原结算保持不变。
- 同一设备记录重复导入时合并。系统发现可能和手填记录重复时，提示用户选择合并或确认为另一场训练。重复同步、重新打开和重复点击确认都只产生一份计划结果和一次对应的宠物变化。

| 当前状态 | 条件 | 下一状态 |
| --- | --- | --- |
| 待训练 | 截止前确认一场达标训练 | 已完成 |
| 待训练 | 到达截止，尚未确认达标训练 | 待补记 |
| 待补记 | 24 小时窗口内确认一场按时完成的训练 | 已完成 |
| 待补记 | 补记窗口关闭，仍无已确认的达标记录 | 已漏练 |
| 已漏练 | 7 天窗口内确认一条符合更正规则的设备记录 | 已完成 |

### 4.3 宠物结算

- 单只宠物从 3 格血开始。完成一次计划推进一次成长，血量保持原值。每项确认漏练扣 1 格血。归零时宠物死亡。
- 漏练归属于该计划截止时在养的宠物。若截止时没有在养宠物，计划照常结算，之后领养的新宠物无需承担这次漏练。改期后的计划按新截止时间归属。
- 一般完成记录的成长归实际训练结束时在养的宠物。迟到设备记录触发更正时，成长和撤销扣血归原结算关联的宠物。没有关联宠物时，仍更正计划和历史。
- 更正后按该宠物仍有效的漏练次数重新计算剩余血量。血量大于零时可恢复原宠物及其成长进度。如果另有仍有效的漏练使血量保持为零，原宠物维持死亡状态。
- 已领养新宠物时，更正保持新宠物当前状态，由用户主动选择是否恢复原宠物。选择恢复原宠物时，新宠物的成长和血量保留为历史，同一时间只有一只在养。领养或恢复均保留用户的计划和训练历史。
- App 在打开或刷新时按实际截止顺序补齐错过的结算。用户未及时打开 App，窗口仍按原截止时间计算。

### 4.4 时间示例

周四安排了跑步 20 分钟。若周四晚临时有课，用户可以在周五 00:00 前把原计划改到周五，训练截止随之改为周六 00:00。若没有改期，周四 21:00 完成 25 分钟跑步，周五补记可正常计入。

同一条周四的跑步记录若到周日才从设备同步，周六 00:00 已结算的漏练可以更正。用户须在下周五 00:00 前确认关联。周五才跑的 25 分钟可以记入历史，周四计划继续按原规则结算。

## 5. 首测与成功标准

**主指标为两周计划训练完成率。** 每位参与者在入组时约定两周训练计划，按已完成计划数除以入组时承诺的计划数计算。改期沿用原编号，新增训练单独观察，退出后未完成的承诺仍留在分母。最后一项承诺训练截止 24 小时后出初步结果，满 7 天后锁定结果。

| 观察项 | 口径 |
| --- | --- |
| 对比方式 | 在招募规模允许时分为两组。两组享有同样的计划、提醒、记录和成长体验，一组开启扣血与死亡。 |
| 首次漏练后是否恢复训练 | 在观察期内仍有下一项训练的用户中，记录首次漏练后实际完成下一项计划的比例。 |
| 宠物死亡后是否继续训练 | 在观察期内仍有下一项训练的用户中，记录死亡后返回及完成下一项计划的比例。另记后来被更正的死亡，便于解释结果。 |
| 记录与结算是否可靠 | 记录手动与设备完成次数、改期后的完成、扣血后更正次数以及重复记录的处理结果。 |

首测启动前，根据可招募人数和基线约定值得继续的完成率改善幅度。样本小时，同时查看每位参与者的计划结果与退出原因。宠物死亡后几乎无人完成下一次训练，即使总完成率有所上升，也需要先查明原因。

统计仅需计划、记录来源、状态变化和宠物事件。Apple 健康读取范围以训练类型和实际时间、时长为限。首测上传数据时只发送所需事件和匿名参与者编号。

## 6. 开发验收用例

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 拒绝 Apple 健康授权后手动记录一场按时达标的训练 | 计划完成，宠物成长一次，训练可在历史查看。 |
| A02 | 导入一条达标训练，主动确认给计划，设备分类与计划名称不同 | 计划完成，来源显示为设备。 |
| A03 | 单次时长不足，或两场短训练加起来才够目标 | 训练均可留在历史，该计划尚未完成。 |
| A04 | 周四截止前改到同周周五，尝试再改到下一周 | 第一次改期保留同一计划编号并更新提醒。跨周改期被阻止。 |
| A05 | 已完成后改期，或原截止到达后改期 | 计划保持原日期和结算状态。 |
| A06 | 训练实际在周四完成，周五在 24 小时内手动补记 | 由待补记变为已完成，宠物成长一次，血量保持原值。 |
| A07 | 周四计划进入补记，用户在周五新做一场训练 | 新训练进入历史。周四计划仍待补记，到期后按漏练结算。 |
| A08 | 补记期满无达标记录，反复打开或刷新 | 每项漏练只扣 1 格血，累计三项时宠物死亡。 |
| A09 | 已漏练但在 7 天内确认一条按时、达标且未占用的设备记录 | 状态更正为已完成，撤销同一次扣血并补发一次成长。 |
| A10 | 补记期外手动输入，或满 7 天后确认迟到设备记录 | 训练可保存为历史，计划与宠物的原结算保持不变。 |
| A11 | 手填和设备记录属于同一场训练，随后尝试匹配另一项计划 | 合并后只保留一次计入和一次成长，原记录无法同时完成另一项。 |
| A12 | 宠物死亡后领养新宠物，有旧计划正等待 24 小时结算 | 保留训练历史和计划。旧计划在截止时若归属原宠物，其结算只影响原宠物。 |
| A13 | 原宠物因误扣血死亡，合规更正后其血量大于零，且已领养新宠物 | 显示恢复原宠物的选项。用户可选在养宠物，双方成长和血量均保留。 |
| A14 | 死亡后更正一次漏练，但仍有三次有效漏练 | 更正计划和成长记录，宠物血量仍为零。 |
| A15 | 当天无计划，或宠物死亡后暂时没有在养宠物 | 无计划日不扣血。仍有训练时可照常完成与记录，后来领养的新宠物不会承担此前到期的训练。 |

## 7. 开工顺序与待定事项

1. 先实现手动记录的完整流程，跑通排计划、改期、补记、漏练、死亡和重新领养。
2. 再接入 Apple 健康读取、记录关联和重复记录处理，打通 7 天更正与误判恢复。
3. 接上首页提醒、像素成长反馈和首测统计，按第 6 节逐项验收后开始试用。

开工时确定屏幕与动效细节、成长阶段阈值，以及首测样本量和完成率改善目标。首版业务默认采用北京时间、自然周和午夜截止，迟到设备记录从原计划截止起计 7 天。
